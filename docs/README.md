# OctoAcme Project Management Docs

## Purpose
Provide a central entry point for OctoAcme project management knowledge so teammates can quickly understand the project lifecycle, core principles, and the process document to use for each phase of delivery.

## Overview
OctoAcme runs cross-functional projects using a lightweight, structured lifecycle that emphasizes customer-first outcomes, iterative delivery, clear ownership, data-informed decisions, and psychological safety. These docs are designed to help teams move from idea to release with shared expectations, consistent artifacts, and clear communication.

## How the docs fit together
Use these documents as a navigation hub for the full project lifecycle:
1. Start with the [Project Management Overview](./octoacme-project-management-overview.md) for the shared principles, roles, artifacts, and communication cadence.
2. Use [Project Initiation](./octoacme-project-initiation.md) to validate the business need, identify stakeholders, and define success criteria.
3. Move to [Project Planning](./octoacme-project-planning.md) to create the backlog, milestones, Definition of Done, and initial QA approach.
4. Use [Execution & Tracking](./octoacme-execution-and-tracking.md) and [Risk Management & Communication](./octoacme-risks-and-communication.md) during delivery to manage progress, blockers, risks, and stakeholder updates.
5. Follow [Release & Deployment](./octoacme-release-and-deployment.md) to prepare for launch, verify readiness, and reduce release risk.
6. Close the loop with [Retrospective & Continuous Improvement](./octoacme-retrospective-and-continuous-improvement.md) to capture learnings and turn them into action items.
7. Refer to [Roles & Personas](./octoacme-roles-and-personas.md) whenever role expectations or responsibilities need clarification.

## Lifecycle summary
- **Initiation**: define the problem statement, goals, success metrics, stakeholders, and high-level timeline.
- **Planning**: break work into shippable increments, estimate scope, identify dependencies, and align milestones.
- **Execution**: deliver small, testable increments through the project board, PR workflow, demos, and ongoing tracking.
- **Risk & Communication**: maintain the risk register, monitor blockers, and keep stakeholders aligned through regular updates.
- **Release**: confirm acceptance criteria, CI, security scans, release notes, rollback plans, and smoke tests before deployment.
- **Retrospective**: review what went well, what to improve, and track follow-up actions for continuous improvement.

## When to use each document
- Use the **overview** doc when onboarding to the OctoAcme process or aligning a team on principles, roles, and key artifacts.
- Use the **initiation** doc before planning begins and a go/no-go decision is still needed.
- Use the **planning** doc once an initiative is approved and the team needs a delivery plan, backlog, milestones, and dependencies.
- Use the **execution** doc throughout implementation to keep work moving through the board, PR, QA, and review workflow.
- Use the **risk and communication** doc whenever a team needs a single source of truth for risks, status updates, decision asks, or escalation paths.
- Use the **release** doc when a delivery increment is ready for staging or production and launch risk needs to be managed.
- Use the **retrospective** doc after each sprint, milestone, release, or incident to turn learnings into concrete improvements.
- Use the **roles and personas** doc when teammates need clarity on responsibilities, goals, or expected communication patterns.
